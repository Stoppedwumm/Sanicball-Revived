📖 Project Overview

Sanicball-Revived is an extraordinarily fast racing game that has been revived and ported to a new version of Unity. This is a fork of the original Sanicball project, maintaining the fast-paced gameplay while updating the engine and codebase.

Note: The original project is discontinued, and the maintainers will not be accepting pull requests. However, the codebase remains available for learning and understanding the project structure.
Important: This project works best with Unity version 5.3.5f1. Newer versions may require additional adjustments and migration of assets. You can download the specific version from the Unity Archive.

🛠️ Development Guide

Getting Started

Prerequisites:
  • Unity 5.3.5f1 (or newer with compatibility adjustments)
  • Visual Studio or Rider for C# development
  • Blender (for 3D modeling and texture work)
  • Git for version control

Setting Up Development Environment

# 1. Clone the repository git clone https://github.com/Stoppedwumm/Sanicball-Revived.git cd Sanicball-Revived # 2. Open the project in Unity 5.3.5f1 # File > Open Project > Select the Sanicball-Revived folder # 3. Wait for Unity to import all assets (may take several minutes) # 4. Navigate to Assets/Scenes to find playable scenes

Project Navigation

📝 Editing Scripts

Open Assets/Scripts/ in your IDE. C# scripts control all game behavior and can be edited while the engine is running.

🎮 Testing Gameplay

Open a scene from Assets/Scenes/ and press Play in the Unity Editor to test the game.

🎨 Creating Assets

Use Blender for 3D models, then import into Unity. Place source files in appropriate Blend files/ directories.

🏗️ Building Standalone Server

Build the Server subproject with Visual Studio or dotnet CLI for multiplayer hosting.

Common Development Tasks

Adding a New Scene

1. File > New Scene
2. Save in Assets/Scenes/
3. Add GameObjects and components
4. Save and test

Adding Custom Shaders

1. Create new shader file in Assets/Shaders/
2. Write ShaderLab/HLSL code
3. Create Material using the shader
4. Apply to GameObjects

Exporting from Blender

1. Model and rig your asset in Blender
2. File > Export As > Autodesk FBX (.fbx)
3. Copy to appropriate Assets/ folder
4. Unity will auto-import with default settings

Working with Prefabs

1. Create a GameObject with components
2. Drag into Assets/Prefabs/
3. Reuse the prefab throughout scenes
4. Edit prefab directly to update all instances

Version Control Best Practices

Git Guidelines:
  • The .gitignore file excludes Unity's temporary files and build artifacts
  • Always pull before pushing to avoid merge conflicts
  • Create descriptive commit messages for clarity
  • Binary files (FBX, PNG, etc.) can cause merge conflicts—work on them one at a time
  • ProjectSettings/ should be kept in sync across the team

Troubleshooting

Asset Import Issues: If assets don't import correctly, check the Console window for error messages. You may need to adjust import settings in the Inspector.
Scene Loading Errors: Ensure all script references are up-to-date. Missing scripts will appear pink in the Hierarchy.
Shader Compilation: If shaders don't compile, verify ShaderLab syntax and that target platforms are supported.
